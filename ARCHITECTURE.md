# Warbound architecture and development guide

**Purpose:** Fast, reliable orientation for an AI agent or developer making a focused change. Read [AGENTS.md](AGENTS.md) for standing gameplay/CI rules and [TODO.md](TODO.md) for approved priorities. Historical version notes are not a license for new game mechanics.

## Responsibility boundaries

| Responsibility | Owner / entry point | Rules |
|---|---|---|
| Authoritative gameplay state and validation | `scripts/economy_rules.gd` (`create`, `step`, request validators) | Sole source of truth for ownership, costs, diplomacy, progression, simulation mutations and outcomes |
| Simulation scratch data | `scripts/step_frame.gd`, `scripts/combat_frame.gd` | Created for a substep/combat pass; never persisted as an independent state or replicated |
| Pure gameplay helpers | `scripts/combat_kernels.gd`, `scripts/repair_queries.gd`, `scripts/construction_queries.gd`, `scripts/system_geometry.gd`, `scripts/sector_geometry.gd` | No scene ownership, RPC dispatch or separate simulation authority; keep ordered tie-breaking intact |
| Lobby, host authority and RPCs | `scripts/game_session.gd` (autoload `GameSession`) | Retains request validation routing, peer checks, simulation timing, snapshot revision and recovery |
| Snapshot compression | `scripts/snapshot_codec.gd` | Pure map-ore and planet-template deltas and replica encode/decode; GameSession owns wire templates and fallbacks |
| Match input, UI and rendering orchestration | `scripts/match.gd` | Read-only previews via public EconomyRules queries; submit commands through GameSession, not local mutations |
| UI feature helpers | `scripts/match_*_ui.gd`, `scripts/command_card_ui.gd`, `scripts/construction_queue_view.gd` and view modules | Client presentation/state only, no new authoritative gameplay rules |
| Map generation/topology | `scripts/planet_map.gd` | Deterministic seeded layouts; preserve stable rock IDs and path/sector topology |

**Request flow:** Input in `match.gd` → `GameSession.request_*` → host validation/dispatch → `EconomyRules` authoritative mutation → reliable snapshots and unreliable movement updates → client presentation/interpolation. Solo uses the same authority simulation without ENet. New actions must reuse this path and must not add an independent client simulation.

## Simulation phase order

`EconomyRules.step(state, dt)` advances one authoritative simulation substep (currently `GameSession.SIM_STEP = 0.1`) in this order:

1. Reset rock planning budget; refresh current movement fields.
2. **Economy:** taxes/upkeep, simulation time, defection, blockades, local production and construction; initialize live hull lookup.
3. **AI:** diplomacy, routing permissions, economic/military decisions, mining budgets.
4. **Combat/repair preparation:** positions, regeneration, unit orders and withdrawals; resolve combat simultaneously, account for destruction/ownership changes, then salvage threats and resource handoffs.
5. **Formations/orders:** synchronize operations, plan formations/exploration, build service and repair indexes.
6. **Individual hull service and movement** in a duplicate of hull iteration order; then idle wandering, separation and contact correction.
7. **Final sync:** operations, exploration, conquest/objective updates; clear ephemeral indexes and route query caches.

Never rearrange these phases or reuse stale cached routes across ownership changes. Stable IDs, ordering, float precision and simultaneous damage attribution are gameplay contracts. `step_frame.gd` and `combat_frame.gd` document the scratch fields actually used by their stages.

## State ownership and lifecycle

The authoritative `state: Dictionary` is initialized by `EconomyRules.create`. Key families (non-exhaustive; consult source for the current schema):

| Root keys | Meaning / lifetime |
|---|---|
| `map` | Seeded points/fields/topology; ore depletion updates field chunks, so don't assume all map data is immutable |
| `planets` | Indexed systems: ownership, production, stocks, shipyard/infrastructure queues, population, upgrades |
| `ships` | Ordered live hull dictionaries with stable integer IDs, authoritative world positions/headings, cargo, orders, HP |
| `teams`, diplomacy and `military` | Relationships, legacy team groups and strategy metadata; changes may invalidate navigation/safety caches |
| `operations`, `next_operation_id` | Stable formation/operation assignments; maintain IDs and member order |
| `salvage`, `next_salvage_id`, `ship_destructions` | Authoritative pickups and destruction events; never create display-only copies as gameplay state |
| `galactic_credits`, `objectives`, `explored` | Empire economy, conquest and discovery owned by the simulation |
| `elapsed`, `next_id`, `next_ai`, `ai_waves` | Simulation time, identity allocation and host strategic scheduling |

`EconomyRules` also maintains **ephemeral static caches** for military/civilian routing, asteroid avoidance and indexed hull lookups. Cache validity is coupled to step phases, rock depletion, ownership changes and destruction. Treat cache invalidation as part of any refactor, not an incidental optimization. Do not persist per-step indexes in snapshots.

The post-combat survivor working set in `StepFrame` shares ordered hull references and handoff buckets across salvage, logistics and military allocation, after combat resolution and the second withdrawal pass. It retains live entity references, not frozen cargo/eligibility. Withdrawal planning uses an independent, lazy spatial index per preparation pass, never for movement-time safety. Formation movement and subsequent service positions remain separate because those phases change positions.

Civilian logistics retains separate `StepFrame.OrderedHullBuckets` for each owner's handoff and mining rendezvous candidates and for salvage pile IDs. Reconcile exact order and live hull identity at the original snapshot boundaries; rendezvous eligibility is evaluated after passive handoffs, not before. Prune empty owner/cell entries and reset on authority/roster replacement. Candidate lists never cache cargo, stage eligibility, safety, claims or salvage quantities. `persistent_logistics_enabled=false` selects the original rebuilds for parity tests. These are retained bucket arrays, not a replacement for the live logistics simulation.

Combat activity envelopes are conservative bounds over the original integer combat cells, grouped by combat team and rebuilt each combat pass. They may prove a weapon search empty, never select a target or suppress a logical deadline. If a window overlaps hostile occupancy, the existing exact scan runs; pursuit, cooldowns, cloak and combat bookkeeping retain their cadence. The reference combat path can disable envelope filtering for parity tests.

Civilian trade preflight derives ordered resource masks from live stock and threshold predicates for each search; it must not persist negative results across hull work because transfers can create or remove opportunities within a substep. Mining filters unusable chunks before route/depot checks. Empty candidate fast paths retain existing caller deadlines and explicit-job cleanup.

Motion sleep is a derived, state/roster-scoped registry of stable hull IDs and last certified no-op dispatch modes. It is never serialized. Only normalized explicit Hold, active Stop and idle military motion can sleep; the same live guard runs at the original hull work boundary, and changes or expiry fall back to the full path immediately. Combat, economy, service indexing, repair, separation/contact and deadline settlement are not suspended. Removal retires the entry; state/roster replacement resets it. A reference step option disables this optimization for parity tests. This is not yet a general event-driven scheduler.

Independent deadline calendars use timestamp buckets from `StepFrame.DeadlineCalendar`, owned by EconomyRules for the active authority state. Cargo-transfer creation/overwrite/eviction updates the event calendar; expiry runs in economy using the original strict age comparison. Autocast cooldown writers update a separate calendar, reconciled during the existing hull-index pass and retired at movement settlement before separation. Expired cooldowns already read as zero; no gameplay cadence is changed. Calendars contain keys/timestamps only and are not serialized; replacement and removal invalidate entries. Reference steps can disable scheduling for parity tests.

Retry work remains at its existing logical deadline: mining/unload/staging and combat already gate expensive searches by timestamp. Check not-due repair and staging before unnecessary eligibility work; inactive laser/pursuit dispatch retains all observable weapon cooldown fields and falls back for retained targets or blocked pursuit. Construction retains incremental work/crew accounting and live auto-refill, but empty queues need no assignment pass. Absolute-time weapon and construction completion require separate parity work; no time integration change is implied.

Direct travel predicts a bounded empty rock-cell corridor for later samples, owned by EconomyRules and invalidated with the rock index or hull removal. A certificate is usable only when the exact original lookahead and swept step are contained and the existing frozen avoidance neighborhood has no other hull (or steering is already exempt). Cached detours and uncertain geometry use the reference integrator. The sample still uses the same per-step arithmetic, including empty rock sweep interpolation; no interaction/arrival deadlines are skipped and separation/contact remain live. Fixed-budget cardinal legs on a bounded binary lattice additionally evaluate their position from an absolute substep anchor. The exact lattice constraints preserve reference move_toward/empty-sweep arithmetic; any changed budget/target, skipped or repeated tick, or externally changed pose reanchors, and unsafe hull/rock conditions discard the prediction. These derived records are scoped to authority/roster and rock-index lifetime, capped and never serialized. Arbitrary-angle fixed-budget legs may also use an eight-substep window of exact reference samples inside a previously certified empty rock rectangle. Every lookahead and sweep is checked during window creation; reuse requires the consecutive tick, same target/budget, same authoritative prior position, no cached rock detour, surviving corridor and live isolated hull neighborhood. This amortizes corridor verification at the cost of bounded speculative arithmetic; it is not an analytic integration replacement and net performance is unmeasured. Other legs retain incremental integration. All interactions and published positions are still sampled at their existing phases. Explicit military position/sector-entry orders can also bypass the unrelated high-priority dispatch probes when live guards establish they are inactive. The existing local movement/arrival routine still runs, and its manual travel helper owns route normalization and destination resolution once per call. The reference motion-sleep-disabled step retains full dispatch. General analytic trajectories and reduced authoritative polling require further numeric and interaction parity evidence.

Movement avoidance retains ordered capped bucket slots and neighborhood arrays across substeps for one authority state/roster. At the same original frozen-position boundary, reconcile slots in exact snapshot insertion order; update entry coordinates in place, and invalidate the nine affected query cells on any membership/order/length change. Queries reuse entry references but never update during the movement phase. Detach the active index before separation/contact; no other phase can read stale positions. A bounded neighborhood cache and independent full rebuild path (`persistent_avoidance_enabled=false`) preserve testing and lifecycle isolation. This still reconciles every position at the boundary; it does not yet remove fleet-wide iteration.

Separation and contact use distinct retained `StepFrame.OrderedHullBuckets` instances for stable IDs at the frozen previous-position boundary and roster slots at the current-position boundary respectively. Each original pass reconciles exact ordered membership; contact bounds are always recomputed. A singleton occupied cell with no occupied adjacent cells proves there is no candidate at the interaction radius, so its force/eligibility or pair scan can be skipped without changing corrections. Dense and boundary cells use the original ordered loops and movement/sector/rock constraints. Both indexes reset on authority/roster replacement; `persistent_avoidance_enabled=false` retains full rebuilds and reference scans.

The settlement loop now also fills the frozen separation index in surviving roster order, after individual hull work (including warp and removal). Separation collects each final position into the contact index and exact bounds as it completes each hull. The first contact iteration consumes this prepared snapshot; later iterations rebuild at their existing boundaries. This removes two standalone fleet-wide index preparation passes without sharing incompatible positions or changing correction order. Standalone reference rebuilds remain available.

Combat uses separate persistent ordered hull-only cell and sector arrays (`StepFrame.OrderedHullBuckets`) at the original combat snapshot boundary. The active dictionary preserves first-encounter key order; refresh exact hull references, trim stale slots, and detach buckets before appending frame-local station/yard records. Positions, health, teams, hostility, threats, target blocks and damage remain freshly frozen and phase-local. Repair uses `RepairQueries.PersistentDamagedIndex` after combat and formation work: recheck every damaged predicate/repair position, retain only ID/order records and invalidate neighboring sorted candidate caches when membership or original order changes. Live damage and friendship checks remain in the repair consumer. Empty miner sets retire the index; state/roster replacement resets both caches. `persistent_combat_enabled=false` retains original rebuilds for comparison.

`GameSession` owns `economy`, `round_id`, `snapshot_revision`, reliable snapshot/template bookkeeping and visual `motion_samples`. The first reliable state conveys generated map/planet templates; later packets may send compact ore and planet changes, and decoding falls back to full states if incompatible. `snapshot_codec.gd` must preserve wire keys such as `_wire_ore`, `_wire_map_template`, `_wire_planets_compact` and `_wire_planet_template`. Movement packets remain **20 bytes per ship**, at most **57 records per batch**; GameSession owns RPC permissions, revision filters and finite-vector checks. Do not alter message schemas casually.

Client map and fog drawing each own a synchronous projection snapshot (viewport/map size, world center, fit and zoom), released when the callback returns. Asteroid vertices use the same projection arithmetic directly rather than invoking the camera for every rock. The fog celestial renderer retains a single static hidden-rock mesh per field while the exact projection and immutable observed chunks are unchanged; map seed changes clear the cache. Live rotating rock meshes and fog observation rules remain independent. No authoritative state or wire changes.

Fog retains its mask image for a map identity and repaints only changed live-vision cells (departures become explored, arrivals transparent). Initial survey and identity changes rebuild the entire mask; observation of sites and rocks remains independent of image upload. Minimap terrain retains packed line geometry per field/live-hidden layer using the immutable observed rock arrays and current minimap geometry; the shared celestial footprint generator also serves the setup preview. These caches contain no newly hidden live ore.

Independent multi-rate work: an unsuccessful autonomous empty-cargo Freighter trade selection sets the optional simulation-owned `_next_trade_search` hull deadline (0.4 years). Only the idle search waits; first search, successful selection, active routes/cargo, manual interruption and trade toggles clear it. The deadline follows existing hull lifetime and optional snapshot fields; no RPC change. `deadline_schedule_enabled=false` selects immediate retries. Stations without repeat targets clear stale repeat cycles without constructing assignment maps; yards with no autobuild skip eligibility. Resource and population integration, active orders and interaction sampling remain at the original substep frequency. No new staggered scheduling.

The contact pass now reuses `StepFrame.ContactBatch`: dense roster-ordered IDs, frozen current/prior positions, correction vectors and first-touch order. Its owner stages poses during separation and applies results through existing authority constraints. This is derived scratch, not canonical storage; it is never serialized. Civilian threat snapshots are demand-driven, service snapshots can filter explicit target IDs when no Harvester exists, and exploration occupancy is skipped without eligible scouts.

`StepFrame.SeparationBatch` now retains ordered roster-slot buckets, packed stable IDs and frozen previous positions. The settlement loop stages survivors and marks missing prior poses absent; neighborhood slots preserve x/y and roster traversal. The force kernel reads only this frozen batch, and EconomyRules still owns eligibility, clipping, movement commit and heading updates. Independent dictionary reference remains for parity. Neither movement batch is canonical ship storage.

`StepFrame.AvoidanceBatch` replaces the production nested movement-avoidance entries with packed IDs/positions and ordered capped slot neighborhoods. It stages from the original frozen pre-movement positions; the nearest-blocker kernel uses no hull dictionaries and preserves exact tie, endpoint, hold and corridor checks. The old full dictionary rebuild remains an independent reference. The batch is derived, detached at settlement, and never serialized.

Equal-radius adjacent ship sensor source cells are grouped into horizontal runs before disk row expansion. The exact union remains the same. `FogOfWar` owns an optional detached ship-only coverage cache, keyed by the freshly computed source-cell/radius dictionary; all structure sight and current sharing/sensor eligibility remain live. It clears on empty state/map identity change and never serializes or shares with authority. Callers without the optional cache compute the same coverage.

Voronoi `sector_geometry.gd` builds a bounded immutable nearest-region candidate grid for maps with at least 32 sites. Each bin retains ordered site IDs whose minimum distance to an expanded query rectangle can compete with the farthest-corner bound of a known candidate. Conservative margins keep boundary candidates. `region_at` still uses exact squared-distance comparison in original ID order; small/unindexable geometry uses the linear reference. Polygon clipping, borders, links, segment checks and map extent remain unchanged. The index is derived topology, not serialized state.

The private authority worker now opens `begin_authority_hull_scope` on its isolated rules script before its first job and closes it on thread stop. The existing live ID→hull dictionary references persist across jobs; launch/removal helpers update membership, and derived monotonic order tokens permit direct small ordered command/service subsets. Roster identity/count mismatch forces reconciliation; externally editable synchronous/fixture state retains per-step rebuild. Cooldown calendars reconcile on scope/state/roster setup and ordinary schedule/removal writes. Canonical hull dictionaries still own every gameplay field; no separate packed authority or replicated schema is introduced. Do not mutate the private roster directly or share its references across the mailbox.

At the original combat boundary, `_peaceful_combat_possible` checks actual hull/structure owners, current group hostility and live rogue/cloak/target/order/pursuit guards. When no interaction is possible, `_combat` skips full target/health/sector/cell geometry and uses the existing hull stance, retreat and blaster processing plus exact inactive weapon metadata/deadline writes; station/PDS and cloak cleanup still run. If civilian threats are requested the existing frame builder runs in threat-only mode, retaining its exact ordered positions, groups, local-sector signatures and cells. No persistent peace certificate; the full combat path wakes on the same substep whenever proof fails. No new replicated state or reduced update rate.

## Making changes safely

1. Identify the authoritative owner and approved gameplay requirement in AGENTS/TODO; keep speculative ideas in THOUGHTS until agreed.
2. Prefer changing a single domain module. Keep existing EconomyRules public signatures or add a facade; UI must never call underscored EconomyRules methods or mutate the authoritative state.
3. Preserve deterministic array/dictionary iteration, sorted tie-breaking, stable IDs, cost/resource reservation, queue limits, simulation order and cache lifetimes.
4. For a behavior-preserving refactor, compare identical seeded checkpoints from `tests/determinism_probe.gd` on both sides of the change. The CI replay guard checks *repeatability on one version*; it cannot alone prove parity with the previous version.
5. Update only relevant tests and documentation in the same versioned commit. Every commit bumps `project.godot`, with a matching `vMAJOR.MINOR.PATCH:` title. Keep unrelated balance and UI changes out of structural PRs.
6. Verify Godot parser/import, economic rules, solo startup, real ENet peers and targeted benchmarks. Report unrun tests explicitly. Existing CI is deliberately manual-only until the final pass is validated.

## Regression test policy

Automated validation protects **gameplay contracts, system invariants, authority and replication**, not UI geometry. Avoid asserting control names, hierarchy, disabled-state layout, labels, text content, pixel positions, sizes, styling, or interpolation internals in core/solo/ENet smoke tests. Test commands and resulting state via `GameSession` and `EconomyRules`; use visual playtesting or separate non-gating screenshots for appearance reviews. Preserve actual multiplayer connect/disconnect, objective, construction, resource and motion protocol coverage. Gameplay-relevant world-space positions (navigation arrival, collision avoidance, weapon ranges) remain valid simulation tests.

## Test entry points

After `godot --headless --path . --import`:

- `python3 tools/check_gdscript.py` — parses every tracked GDScript.
- `python3 tools/check_ui_rule_boundaries.py` — rejects private EconomyRules calls from match UI.
- `godot --headless --path . --script res://tests/construction_queries_test.gd` — base work/recipe costs, queue lookup and immutable input recipes.
- `godot --headless --path . --script res://tests/snapshot_codec_test.gd` — codec round trip, full-state fallback and malformed-input guards.
- `godot --headless --path . --script res://tests/economy_rules_test.gd` — economy, navigation, combat, construction and related invariants.
- `python3 tools/check_determinism.py` — independent-process seeded AI and battle state hash equality, **same version only**.
- `godot --headless --path . --script res://tests/solo_smoke.gd` — scene/startup authority.
- `.github/workflows/godot-validation.yml` — complete manual workflow: imports, parser, core and solo tests, 2/3-player ENet, disconnect scenarios, 8-player manual stress. The required aggregate `validate` job must pass before automatic triggers are restored.

## Performance measurement (informational, not a release gate)

Run `python3 tools/profile_simulation.py --godot godot --output performance-baseline.json` after importing the project, then compare identical fleet sizes, seeds, scenarios and tick counts on **the same machine** after any performance work. The driver uses `tests/fleet_benchmark.gd` unchanged: 500/1000-hull battle and logistics cases at 1× and 5×, a fixed seed, 100 simulation frames per case. Customize with `--ships 500,2500 --seeds 827,123 --scenarios battle,logistics --speeds 1,5 --ticks 100`. Outputs per-case frame p50/p95/p99, combat/repair and movement stage percentiles, CPU/engine and estimated simulated substeps per wall-clock second. This is a **headless CPU simulation benchmark**, not a graphical FPS measurement. Do not assert fixed millisecond budgets in CI or treat incomparable hardware results as regressions. The manual GitHub workflow also runs these representative cases in an independent non-gating `profile` job and uploads `warbound-headless-profile-RUN_NUMBER` as a 30-day artifact. The profile is not a graphical FPS measurement and does not affect aggregate `validate`.

## Stop conditions and deliberate non-goals

Finish the dedicated cleanup when (a) pure domain responsibilities and client/network boundaries are clear, (b) full manually dispatched validation is green, (c) hot-loop performance is measured, and (d) future features can be implemented without spelunking through unrelated systems. **Do not pursue a zero-line monolith, one-file-per-function, complete ECS rewrite, packed-state migration or UI rewrite merely for aesthetics.** The `match.gd` draw orchestrator and movement packet packing are acceptable to leave in their current controller if they remain stable and measurable.

Unresolved gameplay issues (e.g. asteroid anchor arrival and held freighter handoffs) are tracked separately; do not hide gameplay changes inside cleanup PRs.

## Large-fleet architecture migration (v0.97.70)

Four approved workstreams, measured separately. No lower simulation fidelity or gameplay changes.

1. **Single-writer authority worker:** v0.97.71 implements an opt-in persistent worker for solo/host. It owns a detached canonical state and separate rule script/static caches; `GameSession` routes the same 25 authority command implementations via FIFO intents and publishes detached state copies. The main thread owns peer checks, UI/SceneTree, ENet, revisions and motion packets; the worker performs complete ordered fixed-step batches and gameplay validation. Main polling never joins during play; teardown stops and joins. See the experiment controls below. Enabled by default as of v0.97.72 at user request, with synchronous fallback; validation remains pending.
2. **Packed data:** move frozen hot-loop fields into dense arrays at existing phase boundaries; contact positions now use dense slots on the persistent path. Preserve stable IDs and dictionary authority until a single-writer canonical migration is validated. Next: movement, neighbor queries and contact candidate streams; no float downcast of authoritative health.
3. **Persistent GPU instances:** hull batches now retain packed transform staging by texture and opacity, grow capacity only as necessary, and preserve visible-prefix counts. Next: world-space transforms/camera uniforms, persistent asteroid/ship geometry, pose interpolation and less frequent effect/indicator staging. Verify exact art, fog, zoom, selection and layering.
4. **Native kernels:** optional ordered laser/missile block scans in `native/`; default remains GDScript. Build against matching engine API and precision, require reference parity including ties/boundaries, then compare 500/1000/2000-hull seeded throughput. Expand only after parity to spatial/contact/obstacle kernels; native code must not own a second simulation state.

Acceptance: target 60 FPS at 2,000 ships at 1x and 1,000 at 5x on the user's hardware, measure p50/p95/p99 frame times and simulation throughput independently, retain obstacle response and multiplayer correctness. Targets are not measured results.

### Threaded authority controls (v0.97.72)

Enabled by default in project.godot. Disable before starting a match with `godot --path . -- --warbound-synchronous` or set `warbound/performance/threaded_authority=false`. The existing `--warbound-threaded` flag can opt in when the project setting is false; `--warbound-synchronous` takes precedence. The host/solo only runs the worker; guests continue consuming the same ENet protocol. Do not combine with the native-kernel flag yet. Failure to load/probe a separate rules script or start the thread falls back to synchronous mode with a warning.

- The worker receives a deep copy at start and never hands its canonical state back. It deep-copies accepted command results and complete tick snapshots (including urgent intermediate treaty/outcome states); only detached snapshots cross the result mailbox. Local UI queries use the original rules script and their own caches. No main-thread rule query may touch worker state, nor may worker code touch nodes or RPCs.
- All 25 server command entry points use the same typed simulation command implementations on either path; main thread checks connected membership on receipt and dispatch, worker checks current gameplay eligibility. Queued arrays/dictionaries are copied, not shared; no arbitrary RPC method names are accepted. Accepted commands publish immediately on result delivery; the worker processes jobs in FIFO order. Tick interval, speed multipliers and pause/objective-clock behavior are retained for completed ticks.
- At most one pending tick is retained in addition to the current job; overload coalesces excess timer callbacks, including their clock advancement. This deliberate bounded-backlog policy may reduce effective simulation/calendar rate under sustained overload; it never skips internal substeps of a completed batch. Perf shows worker compute, snapshot-copy duration and overrun count separately. Deep copying the full snapshot and main-thread encoding remain possible bottlenecks.
- Stop and join before clearing a round, returning to lobby, disconnecting or exiting; discard pending work/results. No state replacement from a previous round.
- Manual CI includes `godot --headless --path . --script res://tests/authority_worker_test.gd`: actual worker thread ID, cache separation, 5x reference state, copied command/snapshot isolation, guest speed rejection, pause, FIFO and restart/teardown. The worker test checks default selection. Existing solo and detailed ENet fixtures keep the synchronous reference path because they directly mutate authority state. A separate `network_smoke.gd` threaded mode avoids fixture mutation and verifies commands from every guest, host worker commands, detached snapshot round trips and worker teardown at 2, 3 and 8 peers. All host/client checks pass locally and are in the manual validation matrix. Staggered test-client exit after lobby return avoids spurious disconnect-send errors from concurrent harness teardown; same-machine graphical frame-time/throughput measurements remain required.
