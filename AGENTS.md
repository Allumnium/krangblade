# Warbound — standing project instructions

Read this file, [TODO.md](TODO.md), [THOUGHTS.md](THOUGHTS.md), current repository state, and outstanding pull requests at the beginning of every Warbound development chat/session. Later explicit user directions take precedence over these notes and older README sections.

## Workflow
- Use tabs for leading indentation in all GDScript (`.gd`) and Godot shader (`.gdshader`) files, with a display width of four columns. Do not mix tabs and spaces in indentation. CI checks tracked scripts and shaders; preserve non-indentation whitespace and follow `.editorconfig` in external editors. In Godot, set Text Editor → Behavior → Indent → Type to Tabs and Size to 4.
- Apply the `skip-ci-docs` PR label for documentation-only changes to README.md, AGENTS.md, TODO.md, THOUGHTS.md or THOUGHTS_ARCHIVE.md. CI verifies the entire diff is limited to these files and the mandatory version-only bump in project.godot; any other change runs full validation. The required `validate` check and version checks are never skipped. Do not use commit-message CI skip directives.
- Default to GitHub auto-merge for completed, non-draft PRs after work is finished, only when the aggregate validate check is required on main and repository auto-merge is enabled. Preserve versioned squash titles. Otherwise merge directly after verifying all checks passed; never bypass validation. Report configuration blockers.
- Every Warbound project conversation is a development-enabled session. Use the GitHub connector directly; discover and attempt its tools before claiming a limitation. Never ask the user to switch sessions merely to access the repository.
- The game is **Warbound**. The repository is Allumnium/krangblade; the integration branch is main.
- GitHub connector access has repeatedly worked for reading, creating commits, pushing branches, and merging pull requests. Discover and attempt the actual GitHub tools before declaring access unavailable. If a call fails, inspect the error and try an appropriate alternative; report the specific blocker only if access really fails. Never fabricate a push or a test result.
- For approved implementation requests, make the changes in the repository rather than returning speculative code snippets or asking the user to apply them manually. Commit and push, open a PR, run validation, and merge after the checks pass. Resolve any outstanding PR/checks before building on them. Verify the actual main-branch commit/version and distinguish a pushed branch, merged PR, and validated main branch.
- Increment application/config/version in project.godot in **every commit** using MAJOR.MINOR.PATCH, including follow-up and documentation commits. Main menu reads the same value. Patch for fixes/adjustments, minor for features, major for significant breaking milestones. Preserve CI version checks.
- Every commit message subject must start with the exact resulting application/config/version from project.godot, prefixed with `v`, followed by a colon and a concise description (for example, `v0.4.4: Require versioned commit messages`). This applies to all commits, including fixes, documentation, follow-ups and squash-merge commit titles. When merging, explicitly preserve the final version in the commit subject.
- Godot 4.7 project (CI currently 4.7.2). Keep direct-IP ENet multiplayer usable without Steam for development; Steam integration is a future goal. Preserve one to eight players, flexible teams, lobby chat, and offline AI setup. Do not invent AI strategy or military/gameplay systems that have not been agreed.
- Host/solo authority owns simulation changes. Validate ownership, targets, inputs, and request permissions at the authority; keep local UI and remote snapshots consistent. Extend actual two- and three-peer ENet regression coverage for new commands. Check parsing, imports/metadata, economy, solo, network and disconnect/restart behavior. Do not equate a headless pass with visual or internet-latency verification.
- Avoid flaky fixed waits in multiplayer tests; wait for meaningful synchronized state and completed peer checks. Investigate gameplay and network failures instead of weakening assertions. Track Godot .uid/.import sidecars where applicable. Do not commit editor caches.
- Keep status reporting concise: version, what changed, what passed, whether pushed/merged, and genuine limitations. Do not make the user repeatedly ask whether a commit was pushed. Do not claim to continue work asynchronously.

## Automated testing scope

The UI is expected to evolve frequently. Retire obsolete presentation-only assertions rather than maintaining them after each redesign.
- Test gameplay semantics directly against the simulation and authoritative commands: ownership, costs, refunds, movement, combat, logistics, replication and lifecycle. Keep script parsing, resource import/metadata, startup, solo and real two-peer ENet checks mandatory on non-documentation changes. Extended coverage is scope-selected. ## Interface and visual design
- Minimal, consistent dark sci-fi UI. No unnecessary headings, explanations, duplicate data, filler text, default/normal modifiers, or decorative text. Prefer familiar icons and concise numbers, with exact values and optional details in tooltips.
- Use "star system" (or system) for the gameplay node and "shipyard" in all player-facing wording, never "yard". Procedurally named systems are unique and seed-stable; visible orbiting planets are decorative and not separate gameplay entities.
- Top HUD is one row: empire resources, population, year and Menu. Resource tiles fill using stored inventory relative to the sum of actual owned storage capacities; cargo remains included in numeric empire holdings, not storage fill. Each resource has a 2,000-unit starting cap, expanded to 5,000/12,000/30,000 via warehouse levels. Production/delivery stop adding stock at capacity; full construction refunds are preserved even if temporarily above the cap. No game title, worlds/craft counter, reset button. Menu opens a themed modal before leaving; opening it does not pause the simulation.
- Selected system's left panel shows current population only, non-default production modifiers as clear percentages, six local stock/level/annual output rows, and persistent shipyard cards (including construction and idle states). No population growth rate, saturation bar, carrying-capacity numbers, default manufacturing multiplier, or field count. Economy tab offers repeatable resource-specific buildings and PDS construction; full costs and population requirements use local stocks. No Upgrades tab or standalone resource production levels. All home systems start with baseline production of five non-crystal resources and unchanged starting stocks sufficient for roughly four mixed hulls at the v0.12.2 tripled prices.
- Never let numeric values or resource labels wrap vertically. Use non-wrapping aligned labels, sensible minimum widths, compact K/M/B formatting for large amounts, exact tooltips, and scroll containers where appropriate. Manually inspect actual label sizes/line counts at normal and constrained window sizes; visually inspect screenshots when available. Apply a discovered layout fix to equivalent panels rather than waiting for repeated reports.
- Trade tab shows six independent dual-handle percentage sliders with neutral live inventory fill; no resource dropdown. Preserve dragging across snapshots. Trade percentages use the selected system’s actual warehouse capacity. All resources except Crystals have linear population consumption; Crystal production requires explicit local extraction investment.
- Build and upgrade actions belong on their own cards, with icon-only repeat controls, pending build counts in parentheses, and accessible cancellation. No separate queue panel or five-order limit. Canceling an order refunds allocated materials and turns off the matching repeat flag. Preserve other pending orders; cancel newest matching hull first unless directed otherwise. Repeat hull orders cycle in queue order rather than skipping a resource-starved turn; multiple shipyards can take consecutive turns concurrently. Keep manual scheduling and independent upgrade work intact. Upgrades wait their turn at the relevant shipyard. Shipyard-level upgrade prices triple per level. Preserve population gates, build times and gradual construction. All four hull types require Metals, Plastics, Textiles, Organics and Tech. Shipyards is the first and default tab on selecting a system. Up to three shipyard slots live in the left panel, with a small inline Build button and icon cost breakdown only in the next available vacant slot. All hull material costs are tripled from v0.12.1; the first shipyard remains 480 Metals, the second costs 2k Metals/500 Plastics/500 Textiles/200 Organics/100 Tech/100 Crystals, the third costs three times the second. Reserve contiguous numbered slots at enqueue; construction may progress concurrently but completes in slot order. Cancelling an earlier construction refunds its allocated materials, shifts later construction down one slot at its existing completion fraction, and refunds the excess allocated over the cheaper recipe. Maximum three completed plus pending shipyards per system.
- Fog of war is currently off by default; retain discovery machinery for a future match setting. Asteroid fields have varied shapes and specialized ore mixes, individually positioned finite chunks, and resource-specific mining preferences (all enabled by default). Mining stays at least five game years after arrival. No unapproved regeneration or combat mechanics.

## Design scope
- Low-micro networked territory-control RTS. Prioritize autonomous logistics and meaningful high-level decisions. Physical ships carry resources between local stocks; local thresholds govern trade. Keep current gameplay mechanics intact when making presentation-only changes.
- Discuss unresolved design choices before inventing substantial new mechanics, but use sensible implementation defaults for clearly approved changes. Identify provisional balance and design omissions rather than treating them as settled.
- Keep README/current code authoritative for detailed implementation and tests; update these instructions when a later decision supersedes them.

- Military control uses direct owned fighter selection: click, drag box, Shift-add/toggle, Ctrl+1–9 assign and 1–9 recall control groups; right-click a discovered system or field to issue an immediate lane-routed order. H holds fighters in place and allows local fire; emergency withdrawal supersedes hold, with hold resuming after repair. No policy cards, zones, warmup, or human minimum-size rally. Autonomous combat, repair, physical formation travel and colony settlement remain. Legacy isolated allocation fixtures are not a player command path. Fighters physically occupying hostile systems for 20 uninterrupted years without hostile fighters, surviving shipyards or PDS can capture them; neutral systems require colony ships.

- Render all living ships for every client, friendly or hostile, at all activity states, even if discovery is restricted. Ship outlines identify team; no hiding foreign ships. Test generated maps for visible early AI construction, not just eventual expansion.

- Always show clearly visible territory tint/boundaries beneath the map for owned or fighter-held uncontested sectors; use smooth, consistently sized circular influences with rounded same-team blends, smaller asteroid-field influences, antialiased screen-space outlines and no internal same-team borders. Do not render an enlarged low-resolution spatial raster. Contested sectors lack control shading. This is visual only. Hide system and orbital rings unless the system is selected; keep travel lanes thin and faint.

- Bottom-center time controls offer pause, 1×, 2× and 5×. Each match starts at 1×; solo or the multiplayer host controls speed, guests see the active speed without editing it. Pause halts authoritative fixed-step simulation, not the interface, network or accepted player orders. Keep speed replicated with match state.

- Each living ship owns an authoritative world-space position and heading initialized at construction. All subsequent translation advances toward navigation targets at bounded ship speed. Route/POI and mining state are planning metadata, never a source of position changes. Combat, AI proximity, territory and client poses use the same position; clients interpolate snapshots without independent positional offsets. Preserve lane routing and arrival-gated transfers/colonization. Idle hulls wander locally in same-owner, same-kind formations of up to three ships at their current POI; service transfers require docking at their actual waypoint. Do not invent free-flight routing, acceleration, or collision mechanics without agreement.

- Colony ships may target any discovered neutral star system, regardless of adjacency or intermediate ownership. Use shortest existing lane routes through all systems; intermediate systems are not colonized, and ships are exposed to combat. AI uses the same rules.

- Run independent multiplayer regression scenarios concurrently on isolated CI runners, alongside core parsing, simulation and startup/lifecycle tests. Require the real two-peer round trip on every non-documentation PR; require three-peer, loading-disconnect and host-disconnect checks for all changes outside the explicit presentation-only allowlist, main pushes and manual runs; manual workflow dispatch also runs eight-peer stress coverage. The aggregate validate job requires all jobs to pass. Superseded runs on the same ref may be cancelled. Do not reduce gameplay/network assertions or use shorter timeouts as a substitute for faster execution.

- AI chooses strategic attack/defense objectives and issues the same validated direct fighter orders. Provisional defense share and minimum AI attack strength are unchanged in spirit; playtest pacing. During engagements fighters temporarily deviate from their lanes to circle or pursue live opponents, with bounded movement, then resume orders from actual positions.

- Plastics, Textiles and Tech production scales with population up to 100k productive residents per local production level; civilian demand continues scaling linearly. Completed economy buildings raise output and capacity; values are provisional.

- Fighter formations use persistent operation slots shared across AI/human groups. Maneuver toward lane-relative offset waypoints and common station positions using authoritative world coordinates and the existing speed budget. Combat and pursuit take precedence; no client-only offsets. Disk geometry is provisional; synchronized group pace and mixed hull formations remain outstanding.

- Same-operation fighters on the same directed lane and destination share a slowest-member anchor at 80% speed, with full speed available for catching up. Unengaged fighters cross shared waypoints together. Fighters at <=46 HP individually withdraw to the nearest safe reachable owned shipyard, cease firing and pursuit, dock physically, repair at 10 HP/year only without nearby hostile fighters (two laser ranges), and resume current normal orders at full HP. These speeds, thresholds and free repairs are provisional; no fleet-wide retreat or repair costs are defined.

- Ship and upgrade cards are collapsed by default, with clickable headers and separate construction actions in expanded details. Show effects, actual ship stats, icon recipes and only unmet requirements. Preserve visible shipyard slot/progress feedback and inline vacant Build controls. Collapse on system selection changes, not snapshots. Ship construction consumes population proportionally (fighter 500, logistics 2,000, miner 750, colony 40,000). Leave one resident for ordinary hulls; colony construction waits until the remaining settlers can embark while leaving at least 500 residents. Refund allocated population on cancellation, and use embarked settlers as new colony population. Crew costs are provisional. In v0.19.0 hull Organics inputs returned to pre-tripling values to improve construction at food equilibrium.

- Construction progress bars use amber fill and outline when materials or population block progress, with missing inputs in tooltips; return to normal when unblocked. Resource summary includes a modifier column, omitting normal bonuses. System header includes right-aligned muted owner name tinted by empire color. Lobby assigns unique palette colors; only the owning player may change to a free color while in lobby. Solo assigns distinct colors automatically. Territory and hull outlines use empire identity; teams still determine diplomacy/combat and contested territory.

- Each human or AI empire starts with three mining ships, two fighters and one completed planetary defense battery at its home system, in addition to unchanged home stocks/population. Additional PDS batteries are constructed in Economy, one battery per seeded visual planet, with one pending order per system and exponential 3× successive recipes. Completed batteries shoot hostile ships at system-centered fighter range, double fighter shot damage, one shot/year, with simultaneous damage resolution. No friendly fire; batteries are independently targetable and destructible, metallic frame follows defended planet and a system-scale cue appears when zoomed out. Use existing authority/cancel/refund infrastructure; prices and range origin provisional.

- Compact cards have flat disclosure headers with independent Build/Upgrade/Buy, repeat and always-visible cancel controls; instant purchases have disabled cancel. Population uses the same icon in cost grids, overview and HUD. Shipyard slots require 500/5,000/20,000 residents to operate, retain queued work when offline, and resume when staffed. Miners can reach neutral asteroid anchors through non-hostile lanes and deliver to owned depots.

- Solo setup defaults to one human and three AI on separate teams; unique selectable colors, inline add/remove up to eight, team options limited to roster size, Start Match bottom right for solo, bottom left for multiplayer, and Back top right on both setup screens. Preserve alliances on removal. Resource amounts use metric tons (t/kt/Mt/Gt); retain numerical balance. One expanded card per tab, collapse on tab or inspector exit; left slots are their own accordion. Population labels never wrap.

- Mining field access is shared by nearby star systems (within 1.5× original anchor distance plus field radius); choose a reachable non-hostile approach and owned depot, with actual world-space return and unload. Military graph also connects nearby access systems. A live top HUD resource hover lists all owned systems' latest actual production, civilian demand, construction drains and docked imports/exports/mining deliveries, annualized from the latest simulation step, separately from cargo and storage. No averaging in that tooltip; compact HUD retains rolling holdings trend. No materials become usable before physical docking.

- Ship cards retain unlimited repeat and add finite origin-system maintain targets. Count living hulls plus queued work for replenishment; manual orders may exceed the target. Cancelling an order disables both automatic modes.

- Local overview shows signed latest-step population change including crew allocation, with a live hover explaining demographic change, food equilibrium and crew costs. Resource rows share the live hover panel with local production, consumption, construction and physical deliveries.

- Logistics lens uses consistent 3-by-2 stock/capacity bars at every zoom, with resource icons and directional one-to-three carets beside loaded logistics hulls based on cargo fraction.

- Time controls include 10× for stress testing; the same fixed steps and host-only authority apply. Mining path trees share the local topology/team-invalidated civilian cache; dynamic cargo and depot decisions remain tick-local.

- Economy building repeat orders can be armed when the resource is supported. Finite ship target text accepts only decimal digits; preserve authoritative maintain/repeat semantics.

- Civilian consumption uses freshly produced resources plus at most the local import-target quantity of existing stock per simulation step, across all consumed resources. A zero import target prevents civilian inventory draws. Construction remains unrestricted by this limit.

- Logistics freighters use boxy hulls with seven interchangeable cargo bays displaying actual resource quantities, including mixed and partial bays, sharing a total 30-ton capacity. Logistics lens aggregates inbound/outbound cargo at system perimeters by resource and direction, not at moving hulls.
- Habitation limits positive demographic growth independently of food, using a cubic penalty (1 − (1 − population/capacity)^3, clamped to 0–100%) for earlier slowdown with the same capacity and three habitation improvements doubling capacity each.

- Cancel buttons sit immediately to the right of active construction progress bars and are hidden when idle or on instant purchases. This supersedes earlier always-visible cancel instructions. Shipyard progress cancellation targets the displayed job.

- Finite maintain targets are desired quantities and can be set independently of current build eligibility, including missing shipyards and home-system restrictions. Actual production still respects eligibility. Only explicit target changes or intentional cancellation reset targets.

- Natural production modifiers range from 0.1× to 4×. Repeatable Economy buildings increase output and industrial capacity without a separate production upgrade track. Each recipe excludes its own output resource and uses fixed affordable tiers; all settled worlds bootstrap five non-crystal resources.

- Global resource tiles place icon, total and rate above a storage-capacity strip. Filled portions are subdivided by owned system stock, largest first, with full system names only where they fit; cargo is excluded from the strip.

- Population HUD uses sorted proportional system segments and the same live hover as resources. Show signed habitation growth modifier rather than capacity or food equilibrium figures, including upgrade previews.

- Economy buildings are repeatable timed construction, adding 25% per completed building, and enable extraction when baseline production is zero. When nonfood demand exceeds potential output, reserve 10% of production for construction below 500 tons local stock. Trade switches remain independent and default enabled; disabled thresholds persist.

- Logistics traffic indicators lie on the corresponding first/last route lane at the system endpoint, grouped by resource, lane and direction.

- Completed shipyards have replicated HP (1,000 at level one, 1,000 per level) and slow orbital construction frames. Assigned hulls show outline segments snapping into place then progressive fill using actual job progress. Combat targeting/destruction of shipyards requires further integration.

- Single-system global HUD strips omit system names; population uses the same expanding width as resource tiles. Use “Overpopulation penalty” in demographic and habitation upgrade descriptions.

- Miners approach a physical stand-off point beside the target rock; dual short extraction beams and sparse impact sparks are local presentation. Ship thrust uses bounded procedural particles, culled offscreen and reduced at low zoom. No particle nodes or replicated particle state.

- On successful colonization the colony hull converts into the first level-one shipyard; no duplicate initial shipyard purchase. Colony recipe includes an additional 480 Metals and 30 work. A three-game-year local morph transitions the hull outline into the orbital frame.

- Segmented top-bar labels fall back from full system name to two letters, then one letter, then blank as space decreases. Single-contributor strips remain unlabeled.

- Q/E cycle previous/next owned systems in stable map-index order, wrapping around; focus camera and fit selected system in the playable map area. Ignore shortcuts while editing text or in match menu.

- All discovered systems display their names even when unselected; unselected names use subdued translucent lettering, selected names remain bright. Undiscovered systems remain anonymous.

- Shipyard orbits use authoritative world positions; completed hulls spawn at their assigned frame. Fighters target hostile shipyards when no ship is in range; damage accumulates and destruction removes the frame and assigned construction without refunds. Remaining slots compact. Trade checkboxes share a compact threshold row above the track.

- Always implement approved changes, commit and push. Habitation uses the shared economy section and accordion. Trade sliders use neutral fill and identical handles. In-game menu includes persistent local UI scale (70–130%, 10-point steps, default 90%) and independent Music/SFX volume and mute. Hide future shipyard rows until the previous slot is completed, preserving authoritative construction rules.

- Solo setup uses a compact roster panel and a right-hand game settings panel with optional map seed; Start Match is bottom right.

- Batch related approved work into coherent versioned PRs to reduce CI churn. CI may use the fast tier only for presentation scripts (main, match, ui_theme, space_background) plus approved docs and a version-only bump; unknown paths and substantive project settings changes require full validation. Main pushes and manual runs retain full validation. Imported resources may be cached, but import and metadata checks still run.

- Construction cards use inline vertical progress and no disclosure caret; cancel precedes build/upgrade. Economy repeat toggles use authoritative continuous orders and existing costs/population gates.

- Policies are removed; the logistics lens remains. Prioritize a fully working RTS, then promissory notes independent of policies, then the antimatter/core match loop.

- Provisional elimination: an empire without owned systems can rebuild using surviving colony ships while neutral systems remain. Otherwise it is eliminated, remaining hulls stand down and its commands are rejected. Keep eliminated peers connected for observation and snapshot acknowledgments. Last surviving team wins by conquest; one-team sandboxes do not auto-end. Final match result freezes simulation and permits returning to lobby or reviewing the map. Antimatter victory remains a separate milestone.

- Render the existing system-to-asteroid access lanes even when a field is depleted. Idle formations wander across their current sector using deterministic, varying-radius paths bounded by the local territory disk and nearest-POI bisectors; compact rally, hostile system and contested sector groups preserve military readiness. Stationed enemy patrols physically within the sector contest conquest.

- v0.20.0 supersedes gradual material spending: all material recipes are paid in full from local stock at queue acceptance (including manual, AI, repeat and maintain orders), or the purchase is rejected atomically. Instant purchases retain upfront payment. Crew allocation, construction duration, cancellation refunds and proportional work on compacted shipyard slots remain; compaction refunds the full recipe difference. Repeat hulls save for their next turn rather than skipping it. Miners support mixed selection/control groups and persistent field or rock orders; right-click a system to clear assignment. Explicit mining uses existing discovery, policy, safe lane and physical delivery rules; depleted targets revert to automatic selection. Freighters remain autonomous.

- Selected-system resource deltas show theoretical annual local production minus full civilian demand, before warehouse limits, stock scarcity, trade and one-off construction spending. Positive displayed values are green, negative red and zero white. Use existing actual flow hover breakdowns, with the theoretical calculation distinguished from actual flows. Global HUD rates and underlying economic rules are unchanged.
