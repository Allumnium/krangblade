# Warbound — standing project instructions

Read this file, [TODO.md](TODO.md), [THOUGHTS.md](THOUGHTS.md), current repository state, and outstanding pull requests at the beginning of every Warbound development chat/session. Later explicit user directions take precedence over these notes and older README sections.

## Workflow
- Every Warbound project conversation is a development-enabled session. Use the GitHub connector directly; discover and attempt its tools before claiming a limitation. Never ask the user to switch sessions merely to access the repository.
- The game is **Warbound**. The repository is Allumnium/krangblade; the integration branch is main.
- GitHub connector access has repeatedly worked for reading, creating commits, pushing branches, and merging pull requests. Discover and attempt the actual GitHub tools before declaring access unavailable. If a call fails, inspect the error and try an appropriate alternative; report the specific blocker only if access really fails. Never fabricate a push or a test result.
- For approved implementation requests, make the changes in the repository rather than returning speculative code snippets or asking the user to apply them manually. Commit and push, open a PR, run validation, and merge after the checks pass. Resolve any outstanding PR/checks before building on them. Verify the actual main-branch commit/version and distinguish a pushed branch, merged PR, and validated main branch.
- Increment application/config/version in project.godot in **every commit** using MAJOR.MINOR.PATCH, including follow-up and documentation commits. Main menu reads the same value. Patch for fixes/adjustments, minor for features, major for significant breaking milestones. Preserve CI version checks.
- Every commit message subject must start with the exact resulting application/config/version from project.godot, prefixed with `v`, followed by a colon and a concise description (for example, `v0.4.4: Require versioned commit messages`). This applies to all commits, including fixes, documentation, follow-ups and squash-merge commit titles. When merging, explicitly preserve the final version in the commit subject.
- Godot 4.7 project (CI currently 4.7.2). Keep direct-IP ENet multiplayer usable without Steam for development; Steam integration is a future goal. Preserve one to eight players, flexible teams, lobby chat, and offline AI setup. Do not invent AI strategy or military/gameplay systems that have not been agreed.
- Host/solo authority owns simulation changes. Validate ownership, targets, inputs, and request permissions at the authority; keep local UI and remote snapshots consistent. Extend actual two- and eight-peer ENet regression coverage for new commands. Check parsing, imports/metadata, economy, solo, UI layout, network and disconnect/restart behavior. Do not equate a headless pass with visual or internet-latency verification.
- Avoid flaky fixed waits in multiplayer tests; wait for meaningful synchronized state and completed peer checks. Investigate failures instead of weakening assertions. Track Godot .uid/.import sidecars where applicable. Do not commit editor caches.
- Keep status reporting concise: version, what changed, what passed, whether pushed/merged, and genuine limitations. Do not make the user repeatedly ask whether a commit was pushed. Do not claim to continue work asynchronously.

## Interface and visual design
- Minimal, consistent dark sci-fi UI. No unnecessary headings, explanations, duplicate data, filler text, default/normal modifiers, or decorative text. Prefer familiar icons and concise numbers, with exact values and optional details in tooltips.
- Use "star system" (or system) for the gameplay node and "shipyard" in all player-facing wording, never "yard". Procedurally named systems are unique and seed-stable; visible orbiting planets are decorative and not separate gameplay entities.
- Top HUD is one row: empire resources, population, year and Menu. Resource tiles fill using stored inventory relative to the sum of actual owned storage capacities; cargo remains included in numeric empire holdings, not storage fill. Each resource has a 2,000-unit starting cap, expanded to 5,000/12,000/30,000 via warehouse levels. Production/delivery stop adding stock at capacity; full construction refunds are preserved even if temporarily above the cap. No game title, worlds/craft counter, reset button. Menu opens a themed modal before leaving; opening it does not pause the simulation.
- Selected system's left panel shows current population only, non-default production modifiers as clear percentages, six local stock/level/annual output rows, and persistent shipyard cards (including construction and idle states). No population growth rate, saturation bar, carrying-capacity numbers, default manufacturing multiplier, or field count. Economy tab offers once-per-system permanent buildings with resource-specific +25% output (Organics boosts farm potential); full costs and population requirements use local stocks. All home systems start with baseline production of five non-crystal resources and unchanged starting stocks sufficient for roughly four mixed hulls at the v0.12.2 tripled prices.
- Never let numeric values or resource labels wrap vertically. Use non-wrapping aligned labels, sensible minimum widths, compact K/M/B formatting for large amounts, exact tooltips, and scroll containers where appropriate. Test actual label sizes/line counts at normal and constrained window sizes; visually inspect screenshots when available. Apply a discovered layout fix to equivalent panels rather than waiting for repeated reports.
- Trade tab shows six independent dual-handle percentage sliders with resource-colored live inventory fill; no resource dropdown. Preserve dragging across snapshots. Trade percentages use the selected system’s actual warehouse capacity. All resources except Crystals have linear population consumption; Crystal production requires explicit local extraction investment.
- Build and upgrade actions belong on their own cards, with icon-only repeat controls, pending build counts in parentheses, and accessible cancellation. No separate queue panel or five-order limit. Canceling an order refunds allocated materials and turns off the matching repeat flag. Preserve other pending orders; cancel newest matching hull first unless directed otherwise. Repeat hull orders cycle in queue order rather than skipping a resource-starved turn; multiple shipyards can take consecutive turns concurrently. Keep manual scheduling and independent upgrade work intact. Upgrades wait their turn at the relevant shipyard. Resource-production and shipyard-level upgrade prices triple per level (starting at 200 and 240 Metals for level 1 respectively); warehouse logistics prices triple per level (500/1,500/4,500 Metals plus proportional Plastics and Tech). Permanent single-purchase economic building prices also triple from v0.12.2, independently of purchase order. Preserve population gates, build times and gradual construction. Local resource-production upgrades require population; the first Tech upgrade requires 200k. Repeat production waits for later population gates. All four hull types require Metals, Plastics, Textiles, Organics and Tech. Shipyards is the first and default tab on selecting a system. Three shipyard slots live in the left panel, with a small inline Build button and icon cost breakdown only in the next available vacant slot. All hull material costs are tripled from v0.12.1; the first shipyard remains 480 Metals, the second costs 2k Metals/500 Plastics/500 Textiles/200 Organics/100 Tech/100 Crystals, the third costs three times the second. Reserve contiguous numbered slots at enqueue; construction may progress concurrently but completes in slot order. Cancelling an earlier construction refunds its allocated materials, shifts later construction down one slot at its existing completion fraction, and refunds the excess allocated over the cheaper recipe. Maximum three completed plus pending shipyards per system.
- Fog of war is currently off by default; retain discovery machinery for a future match setting. Asteroid fields have varied shapes and specialized ore mixes, individually positioned finite chunks, and resource-specific mining preferences (all enabled by default). Mining stays at least five game years after arrival. No unapproved regeneration or combat mechanics.

## Design scope
- Low-micro networked territory-control RTS. Prioritize autonomous logistics and meaningful high-level decisions. Physical ships carry resources between local stocks; local thresholds govern trade. Keep current gameplay mechanics intact when making presentation-only changes.
- Discuss unresolved design choices before inventing substantial new mechanics, but use sensible implementation defaults for clearly approved changes. Identify provisional balance and design omissions rather than treating them as settled.
- Keep README/current code authoritative for detailed implementation and tests; update these instructions when a later decision supersedes them.

- Military lens provides direct normalized fighter allocations (total 100%) at every discovered POI, including all star systems and asteroid fields. No separate outpost declarations, patrol or frontier settings. Closest available ships by remaining lane travel distance satisfy integer fleet quotas; reassign on policy/fleet changes and allow continuous mid-leg reversal. Military may traverse any star lane; fields are approached via their service anchor. Start at 100% home. Fighters auto-engage hostile ships within world-space laser range; simultaneous damage, six hits per basic hull. AI slots use the same economy and allocation rules, autonomously expanding through reachable neutral systems and seeking enemy ships. No conquest of owned systems or direct retreat command yet.

- Render all living ships for every client, friendly or hostile, at all activity states, even if discovery is restricted. Ship outlines identify team; no hiding foreign ships. Test generated maps for visible early AI construction, not just eventual expansion.

- Always show clearly visible territory tint/boundaries beneath the map for owned or fighter-held uncontested sectors; use smooth, consistently sized circular influences with rounded same-team blends, smaller asteroid-field influences, antialiased screen-space outlines and no internal same-team borders. Do not render an enlarged low-resolution spatial raster. Contested sectors lack control shading. This is visual only. Hide system and orbital rings unless the system is selected; keep travel lanes thin and faint.

- Bottom-center time controls offer pause, 1×, 2× and 5×. Each match starts at 1×; solo or the multiplayer host controls speed, guests see the active speed without editing it. Pause halts authoritative fixed-step simulation, not the interface, network or accepted player orders. Keep speed replicated with match state.

- Each living ship owns an authoritative world-space position and heading initialized at construction. All subsequent translation advances toward navigation targets at bounded ship speed. Route/POI and mining state are planning metadata, never a source of position changes. Combat, AI proximity, territory and client poses use the same position; clients interpolate snapshots without independent positional offsets. Preserve lane routing and arrival-gated transfers/colonization. Idle hulls navigate to physical station positions; service transfers require docking at their actual waypoint. Do not invent free-flight routing, acceleration, or collision mechanics without agreement.

- Colony ships may target any discovered neutral star system, regardless of adjacency or intermediate ownership. Use shortest existing lane routes through all systems; intermediate systems are not colonized, and ships are exposed to combat. AI uses the same rules.

- Run independent multiplayer regression scenarios concurrently on isolated CI runners, alongside core parsing, simulation and UI tests. Keep both real two-/eight-peer round trips, loading-disconnect and host-disconnect checks mandatory; the aggregate validate job requires all jobs to pass. Superseded runs on the same ref may be cancelled. Do not reduce assertions or use shorter timeouts as a substitute for faster execution.

- AI fighters rally at their home system and launch in cohorts of at least three physically assembled hulls on a shared objective. New reinforcements stay in reserve during a wave; survivors regroup when the objective is reached and engagement ends or only one unengaged survivor remains. Human hostile-owned system allocations now also rally at home in cohorts of at least three, with new reinforcements launching in assembled cohorts and lone unengaged survivors regrouping; friendly and neutral POI allocations remain immediate. During engagements fighters temporarily deviate from their lane to circle live opponents, with bounded world-space movement toward a preferred engagement distance; when combat ends they resume queued waypoints from their actual position. Fighters chase hostile non-fighters and fleeing fighters for up to three game years, including beyond weapon range without firing. Cohort size, hostile-objective distinction, pursuit duration and orbit geometry are provisional; retreat rules remain undecided.

- Plastics, Textiles and Tech production scales with population up to 100k productive residents per local production level; civilian demand continues scaling linearly. Upgrade levels and permanent economy buildings raise output; values are provisional.

- Fighter formations use persistent operation slots shared across AI/human groups. Maneuver toward lane-relative offset waypoints and common station positions using authoritative world coordinates and the existing speed budget. Combat and pursuit take precedence; no client-only offsets. Disk geometry is provisional; synchronized group pace and mixed hull formations remain outstanding.

- Same-operation fighters on the same directed lane and destination share a slowest-member anchor at 80% speed, with full speed available for catching up. Unengaged fighters cross shared waypoints together. Fighters at <=46 HP individually withdraw to the nearest safe reachable owned shipyard, cease firing and pursuit, dock physically, repair at 10 HP/year only without nearby hostile fighters (two laser ranges), and resume current normal orders at full HP. These speeds, thresholds and free repairs are provisional; no fleet-wide retreat or repair costs are defined.

- Ship and upgrade cards are collapsed by default, with clickable headers and separate construction actions in expanded details. Show effects, actual ship stats, icon recipes and only unmet requirements. Preserve visible shipyard slot/progress feedback and inline vacant Build controls. Collapse on system selection changes, not snapshots. Ship construction consumes population proportionally (fighter 10, logistics 20, miner 30, colony 1,000); leave one resident, refund allocated population on cancellation, and use embarked settlers as new colony population. Crew costs are provisional.

- Construction progress bars use amber fill and outline when materials or population block progress, with missing inputs in tooltips; return to normal when unblocked. Resource summary includes a modifier column, omitting normal bonuses. System header includes right-aligned muted owner name tinted by empire color. Lobby assigns unique palette colors; only the owning player may change to a free color while in lobby. Solo assigns distinct colors automatically. Territory and hull outlines use empire identity; teams still determine diplomacy/combat and contested territory.

- Each human or AI empire starts with three mining ships and two fighters, in addition to unchanged home stocks/population. PDS is a constructed upgrade, one battery per seeded visual planet, with one pending order per system and exponential 3× successive recipes. Completed batteries shoot hostile ships at system-centered fighter range, double fighter shot damage, one shot/year, with simultaneous damage resolution. No friendly fire or independent PDS destruction; metallic frame follows defended planet and a system-scale cue appears when zoomed out. Use existing authority/cancel/refund infrastructure; prices and range origin provisional.

- Compact cards have flat disclosure headers with independent Build/Upgrade/Buy, repeat and always-visible cancel controls; instant purchases have disabled cancel. Population uses the same icon in cost grids, overview and HUD. Shipyard slots require 500/5,000/20,000 residents to operate, retain queued work when offline, and resume when staffed. Miners can reach neutral asteroid anchors through non-hostile lanes and deliver to owned depots.

- Solo setup defaults to one human and three AI on separate teams; unique selectable colors, inline add/remove up to eight, team options limited to roster size, Start Match bottom left and Back top right on both setup screens. Preserve alliances on removal. Resource amounts use metric tons (t/kt/Mt/Gt); retain numerical balance. One expanded card per tab, collapse on tab or inspector exit; left slots are their own accordion. Population labels never wrap.

- Mining field access is shared by nearby star systems (within 1.5× original anchor distance plus field radius); choose a reachable non-hostile approach and owned depot, with actual world-space return and unload. Military graph also connects nearby access systems. A live top HUD resource hover lists all owned systems' latest actual production, civilian demand, construction drains and docked imports/exports/mining deliveries, annualized from the latest simulation step, separately from cargo and storage. No averaging in that tooltip; compact HUD retains rolling holdings trend. No materials become usable before physical docking.

- Ship cards retain unlimited repeat and add finite origin-system maintain targets. Count living hulls plus queued work for replenishment; manual orders may exceed the target. Cancelling an order disables both automatic modes.

- Local overview shows signed latest-step population change including crew allocation, with a live hover explaining demographic change, food equilibrium and crew costs. Resource rows share the live hover panel with local production, consumption, construction and physical deliveries.

- Logistics lens uses consistent 3-by-2 stock/capacity bars at every zoom, with resource icons and directional one-to-three carets beside loaded logistics hulls based on cargo fraction.

- Time controls include 10× for stress testing; the same fixed steps and host-only authority apply. Mining path trees share the local topology/team-invalidated civilian cache; dynamic cargo and depot decisions remain tick-local.

- Repeat production upgrades can be armed before population or resources are sufficient, provided the system supports that resource; actual construction gates remain unchanged. Finite ship target text accepts only decimal digits; unlimited repeat remains separate.

- Civilian consumption uses freshly produced resources plus at most the local import-target quantity of existing stock per simulation step, across all consumed resources. A zero import target prevents civilian inventory draws. Construction remains unrestricted by this limit.

- Logistics freighters use boxy hulls and six resource-tinted cargo bays. Logistics lens aggregates inbound/outbound cargo at system perimeters by resource and direction, not at moving hulls.
- Habitation limits positive demographic growth independently of food, with a size-based soft capacity and three economy technology upgrades doubling capacity each. Values provisional.

- Cancel buttons sit immediately to the right of active construction progress bars and are hidden when idle or on instant purchases. This supersedes earlier always-visible cancel instructions. Shipyard progress cancellation targets the displayed job.

- Finite maintain targets are desired quantities and can be set independently of current build eligibility, including missing shipyards and home-system restrictions. Actual production still respects eligibility. Only explicit target changes or intentional cancellation reset targets.

- Generated system production modifiers range from −90% to +300% (0.1× to 4×), including the effective building multiplier. Poor deposits permit extraction; zero population or unbuilt production levels still yield zero output.

- Global resource tiles place icon, total and rate above a storage-capacity strip. Filled portions are subdivided by owned system stock, largest first, with full system names only where they fit; cargo is excluded from the strip.

- Population HUD uses sorted proportional system segments and the same live hover as resources. Show signed habitation growth modifier rather than capacity or food equilibrium figures, including upgrade previews.

- Resource economy buildings are repeatable timed construction, adding 25% per completed building subject to the existing production bounds. Trade import/export switches are independent and default enabled; disabled thresholds persist, and dragging either enabled handle pushes the other when crossing.

- Logistics traffic indicators lie on the corresponding first/last route lane at the system endpoint, grouped by resource, lane and direction.

- Completed shipyards have replicated HP (1,000 at level one, 1,000 per level) and slow orbital construction frames. Assigned hulls show outline segments snapping into place then progressive fill using actual job progress. Combat targeting/destruction of shipyards requires further integration.

- Single-system global HUD strips omit system names; population uses the same expanding width as resource tiles. Use “Overpopulation penalty” in demographic and habitation upgrade descriptions.

- Miners approach a physical stand-off point beside the target rock; dual short extraction beams and sparse impact sparks are local presentation. Ship thrust uses bounded procedural particles, culled offscreen and reduced at low zoom. No particle nodes or replicated particle state.

- On successful colonization the colony hull converts into the first level-one shipyard; no duplicate initial shipyard purchase. Colony recipe includes an additional 480 Metals and 30 work. A three-game-year local morph transitions the hull outline into the orbital frame.

- Segmented top-bar labels fall back from full system name to two letters, then one letter, then blank as space decreases. Single-contributor strips remain unlabeled.

- Q/E cycle previous/next owned systems in stable map-index order, wrapping around; focus camera and fit selected system in the playable map area. Ignore shortcuts while editing text or in match menu.

- All discovered systems display their names even when unselected; unselected names use subdued translucent lettering, selected names remain bright. Undiscovered systems remain anonymous.
